Walkthrough

Control tmux sessions easily in iTerm2, with crash-safe restore.

This project installs a launchd save loop for tmux-resurrect, adds a restore picker, and gives you a simple iTerm2-first tmux-session launcher.

Mental Model

The launcher always uses tmux -CC attach. That is iTerm2's native tmux integration, and its behavior is non-obvious until you see it:

Control channel

The iTerm2 window you run tmux-session from becomes the -CC control channel — you'll see iTerm2's "Command Menu / esc Detach cleanly" prompt. Minimize it; don't work there. Press esc in it to detach the session cleanly.

Working windows

For each tmux window in the session, iTerm2 spawns a separate native iTerm2 window (or tab, depending on your iTerm2 prefs). Those are where you actually work. They get real Cmd-Tab / Mission Control treatment, not a tmux mux inside one terminal.

Pane

A tmux pane is a split inside a window. This is where shells, editors, Codex, and long-running commands live.

Daemon

One launchd job snapshots tmux state every 15 minutes via tmux-resurrect. iTerm2's tmux UI is not a second daemon.

Two sessions in parallel: open a second fresh iTerm2 window via Shell → New Window (not Cmd-T inside the attached window) and run another tmux-session --session <name> --resume there. Each session gets its own control channel and its own native working windows. Default session is main (override with --session <name> or TMUX_SESSION_NAME).
Refused inside tmux: running --resume or --create from inside an existing tmux pane is refused, with a hint pointing at tmux new-window -n <name> -c <dir> for the "add a tab here" case. (The old switch-client behavior silently hijacked the current connection.)

Install

Run this once from the repo. It installs the save, restore, precheck, and session launcher commands into ~/.local/bin, then registers the launchd job.

install
$ git clone https://github.com/omriariav/tmux-resurrect-launchd.git
$ cd tmux-resurrect-launchd
$ ./install.sh

Verify the install:

verify
$ launchctl list | grep tmux-resurrect-save
$ tail ~/Library/Logs/tmux-resurrect-save.log
$ tmux-resurrect-restore --list | head
$ tmux-session ls

Daily Flow

Resume your main tmux session

Run this from a fresh iTerm2 window (the one it runs in becomes the -CC control channel; iTerm2 spawns separate native windows for the session's tmux windows).

resume
$ tmux-session --resume

See what sessions exist

ls prints every session on the tmux server with its tabs, panes, and an (attached, N clients) marker for live ones. Pair with --session <name> --list to scope to a single session.

list
$ tmux-session ls

session: main (attached, 1 client)
   0: pm-os         (1p)  /Users/omri.a/Code/taboola-pm-os
     * pane 0  %12  zsh    /Users/omri.a/Code/taboola-pm-os
   1: data-track    (2p)  /Users/omri.a/Code/data-track-map
     * pane 0  %13  vim    /Users/omri.a/Code/data-track-map
       pane 1  %14  zsh    /Users/omri.a/Code/data-track-map
 * 2: handoff       (4p)  /Users/omri.a/Code/handoff
     * pane 0  %15  zsh    /Users/omri.a/Code/handoff
       pane 1  %16  node   /Users/omri.a/Code/handoff

session: work
   0: api           (1p)  /Users/omri.a/Code/api
     * pane 0  %19  zsh    /Users/omri.a/Code/api

Create a tab for a project — and attach in one shot

--create already attaches via tmux -CC attach; no follow-up --resume needed. If the session doesn't exist, it's created with the named tab as its only window. If the tab already exists, the launcher selects it instead of duplicating.

create tab
$ tmux-session --create taboola-pm-os ~/Code/taboola-pm-os

Run a second session in parallel

Open a second fresh iTerm2 window via Shell → New Window (so it isn't already inside tmux), then attach the other session there.

named session
$ tmux-session --session work --resume
$ tmux-session --session work --create api ~/Code/api
$ TMUX_SESSION_NAME=work tmux-session --resume

Delete windows or panes

Use --delete or --delete-window for a whole window by index or current name. Use --delete-pane with a window ref and pane index or pane id from ls.

delete
$ tmux-session --delete notes
$ tmux-session --delete-window 2
$ tmux-session --delete-pane api 1
$ tmux-session --delete-pane api '%13'

Clean up window names

tmux's automatic-rename can overwrite your tab name with the foreground process (codex-aarch64-a, version tags, etc.). --rename-all walks every window and renames it to basename(active pane's cwd), flipping each to manual-name mode so the new name sticks. Windows whose active pane sits in $HOME are skipped.

rename
$ tmux-session --rename-all
$ tmux-session --rename 0 pm-os
$ tmux-session --rename codex-aarch64-a notes

Backup Loop

The launchd job runs tmux-resurrect-save every 15 minutes and at install time. It does not depend on tmux's status bar, which is the part that can fail under iTerm2 control mode.

Piece What it does Where to look
launchd Runs the periodic save job. ~/Library/LaunchAgents/com.user.tmux-resurrect-save.plist
save Calls tmux-resurrect through tmux run-shell. ~/.local/bin/tmux-resurrect-save
snapshots Stores timestamped tmux-resurrect files. ~/.tmux/resurrect/
logs Shows save success, skips, and guard decisions. ~/Library/Logs/tmux-resurrect-save.log
Regression guard: if a real multi-pane session is replaced by an empty one-pane post-reboot state, the save script keeps the old last pointer so recovery stays useful.

Restore After Crash Or Reboot

Run restore from a fresh shell that is not already inside tmux. The picker separates pre-boot snapshots from post-boot snapshots and recommends the newest useful recovery point.

restore
$ tmux-resurrect-restore

Useful restore forms:

restore variants
$ tmux-resurrect-restore --list
$ tmux-resurrect-restore --restore latest-good
$ tmux-resurrect-restore --restore latest-good --no-confirm
$ tmux-resurrect-restore --restore 20260503T143047
Rule: --list is safe inside tmux. Actual restore is intentionally blocked inside tmux because it needs to restart the tmux server.

iTerm2 Palette

The active palette is slick-green. It keeps the green terminal look, avoids unreadable dark green text, and uses FiraCode Nerd Font Mono at size 16 with line height 1.2 in the saved iTerm2 profile.

palette

$ ./palette_preview.sh slick-green-other-font

Troubleshooting

Shift+Enter does not create a new line

Confirm tmux extended keys are off. This setup keeps them disabled because that restores the expected multiline behavior.

keys
$ tmux show-options -s extended-keys
extended-keys off

Command or Option arrows do not move across the line

Command+Left and Command+Right should move to the start and end of the line. Option+Left and Option+Right should move by word. The iTerm2 profile needs explicit key mappings: Option+Left sends 0x1b 0x62, and Option+Right sends 0x1b 0x66.

arrows
$ zsh -ic 'bindkey' | grep -E '"\\^\\[b"|"\\^\\[f"'
"^[b" backward-word
"^[f" forward-word

Text becomes black or unreadable

Reapply the saved palette from an iTerm2 shell. If a temporary preview profile is active, this switches back to omri and removes the preview file.

colors
$ cd ~/Code/tmux-resurrect-launchd
$ ./palette_preview.sh slick-green

iTerm2 shows native tmux controls

That is expected when tmux-session attaches with tmux -CC. It means iTerm2 is rendering tmux sessions as native windows, tabs, and panes.

Dynamic Profile JSON warning appears

The preview script validates JSON before moving it into iTerm2's watched directory. If an old broken temp file remains, remove the codex-palette-preview* files and apply slick-green again.

dynamic profiles
$ find "$HOME/Library/Application Support/iTerm2/DynamicProfiles" -name 'codex-palette-preview*' -print
$ ./palette_preview.sh slick-green

Check daemon health

daemon
$ launchctl print "gui/$(id -u)/com.user.tmux-resurrect-save"
$ tail -n 50 ~/Library/Logs/tmux-resurrect-save.log

Open this file directly in a browser. No local server is required.
